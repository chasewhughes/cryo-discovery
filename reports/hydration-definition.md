# Phase 11 hydration descriptor audit

Phase 11 freezes `cryo-nearest-water-v1` as an explicitly new representation. For each saved frame, every solvent oxygen is assigned its minimum-image distance to the nearest solute atom (all solute atoms, including hydrogens). Each water contributes once to cumulative counts at 0.20–0.50 nm and to a 100-bin, 0–0.50 nm conditional PDF. Each frame is normalized by its in-range water count and 0.005 nm bin width, then frame PDFs are averaged. Bins are left closed/right open except the final bin, and count cutoffs are inclusive; exact-edge values therefore follow IEEE floating-point and NumPy boundary behavior.

The isolated MD environment reanalyzed all six saved Phase 10 trajectories. Recomputed unique-water count arrays match the saved arrays exactly (`max absolute difference = 0`). Every frame PDF integrates to 1 within floating-point roundoff. Mean 0.30 nm counts are 10.9667 for glycine and 15.19 for L-phenylalanine. The implementation agrees with the prior Phase 10 nearest-water post hoc result for glycine (total variation 6.57×10⁻¹⁶); phenylalanine differs by 6.54×10⁻⁵. Root reproduced the original Phase 10 float32 subtraction/norm and histogram arithmetic, which recovers both stored summaries to machine precision. The new implementation explicitly promotes saved coordinates to float64 before distance calculation. This explains the small representation difference on identical saved coordinates; it does not recover precision lost when trajectories were stored as float32. The original arithmetic comparison is retained in the audit script.

Per-seed total variation against the archived DOLMEN histogram is 0.0601–0.0744 for glycine and 0.0476–0.0578 for phenylalanine. These are representation-shape diagnostics, not prediction errors. The archived source comparison does not establish that nearest-water was used by DOLMEN. The paper describes all water-oxygen to all-solute-atom pairwise distances, while public HIN contains several modes and separate radial normalization. The original generator, frame times, state/topology choices and postprocessing remain unresolved. Accordingly, this version is useful for transparent water occupancy and stability/sensitivity work, while all-pairs histograms remain a secondary sensitivity representation.

Exact inputs, hashes, checks and limitations are recorded in [descriptor-audit.json](../data/phase11/descriptor-audit.json). The audit is read-only and adds no simulations, labels or model fitting.
